Описание и задачи


В каждую очередь может писать только один процесс.
Один процесс может писать в несколько очередей.
Из каждой очереди могут читать несколько процессов.



Конструктор - для создания сразу защищенного объекта с параметрами. (вызывает конструктор объекта) 
Функции - для добавления параметров. 



Интерфейс - это класс буферов FIFO

И все - асинхронно - доступ через мьютексы
Асинхронность:
- только на запись (читает - только один объект, пишет - не один объект)
- только на чтение (читает - не один объект, пишет - только один объект)
- на чтение и запись (и читают и пишут много объектов)

Отдельно - обработка ошибок:
класс обработчика, коды, сообщения, 

Для каждой очереди можно задать:
- ID (автоматически) - новый при каждом создании
- Имя - можно задавать для передачи другим субъектам
- Тип данных
- Длину
- статус (readonly) - пустая, очищена, заполнена, переполнена, ОШИБКА, остановка

Доступ - мандатный: на основе прав на каждую очередь (enum):
- не вижу (имя ID и т.п.) и ничего не могу сделать (0)
- вижу (имя ID и т.п.) (1)
- + могу читать данные из начала (2)
- + могу менять маркер записи
- + могу удалять считанную запись
- + могу читать данные откуда угодно
- + могу писать данные стандартно - в конец
- + могу писать данные куда угодно
- + могу очистить всю очередь и т.п.
- + могу удалить очередь - создатель



У каждой очереди есть создатель. Он может очистить очередь, удалить её, изменить длину.

Очередь может быть readonly - для всех, кроме создателя. 

Создатель может передавать другим имя очереди (или ID) с правами(? или права - отдельно?). Как реализовать механизм защиты - чтобы никто посторонний не влез в чужую очередь? - мандатный доступ

Статус - можно или нельзя сбрасывать несчитанную запись в конце очереди?

1 вариант работы: очередь заполняется сверху, и когда заполнена последняя снизу - снизу начинают сбрасываться по мере поступления новых верхних. Независимо от чтения.

Очередь-кольцо, в который пишется - независимо ни от чего.

2 вариант: очередь заполняется сверху, и когда заполнена последняя снизу - снизу начинают сбрасываться по времени? - как???. Независимо от чтения.

3 вариант: очередь заполняется сверху и считывается снизу на одну или более позиций. снизу сбрасываются только прочитанные - по мере заполнения очереди. А дальше - либо остановка - по варианту 5, либо сброс по варианту 4.

4 вариант: очередь заполняется сверху и считывается снизу и в произвольных местах. сбрасываются (сначала) только прочитанные, затем - нижние непрочитанные.

5 вариант: очередь заполняется сверху и считывается снизу и в произвольных местах. сбрасываются только прочитанные, затем наступает переполнение и остановка до момента чтения какой-то записи.


Тогда каждой очереди нужен свой буферный регистр, в который пишутся новые данные. А потом из этого регистра - записываются или нет в очередь - по мере освобождения верхушки. В регистр можно писать всегда.



Всегда есть: фактическая длина очереди (size) и длина заполнения (length)

Каждая запись содержит:
ID
Время (до миллисекунд (микросекунд)) - сделать выбор при создании
Данные (int или long > 0 или что-то другое)
Маркер записи (считан - не считан, еще что-то???)



индекс нижней записи (head - откуда мы начинаем чтение и всегда читаем по одной) - всегда [0]?
верхушка (tail) - всегда максимальное значение, соответствующее размеру заполнения

Есть два режима индексации:
- абсолютный - в исходном массиве
- относительный - относительно головы ([0]) в сторону хвоста (tail - [самый большой относительный индекс])
- и прямые чтение и запись - без индексов


Функционал:
- создать очередь
- убить очередь
- очистить очередь - все = 0
- изменить статус очереди (readonly)
- изменить длину очереди

- запросить не последнюю, а любую произвольную запись из очереди

- запрос к создателю (любой) - отдельная очередь запросов (для чтения всеми создателями)?


По умолчанию:
- создатель создает очередь и пишет в неё
- кто-то другой читает


Своя обработка исключений - в важных случаях
Коды возврата
Функции тестирования и восстановления объектов и данных
Функция логирования с расширенными настройками - в отдельном процессе - чтобы не тормозить основной поток

Резервирование? - Создание дублирующей очереди, в которую пишется автоматически из основной (после каждой записи в основную, если есть дублирующая, о в нее автоматически производится такая же запись), и из которой выполняется чтение при затыках в основной

Отладочные функции  - вывод данных, замер времени
